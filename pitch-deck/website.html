team bevijen presents

A database that keeps itself up to date

We automate how community-service information is checked and updated, so specialists spend less time on upkeep and more time helping people.

chapter 1

where it starts

People need access to community resources

A family looking for a food pantry. Someone who just lost their housing. A parent searching for a clinic they can afford. The help exists in every community, but it only matters if people can find it.

  • Food, shelter, health care, jobs: the services people rely on
  • Resource directories are where many people turn to find them
  • The answer is only as good as the information behind it

chapter 2

the problem

The data changes constantly, but it’s updated by hand

Community services change all the time: phone numbers, hours, locations, programs that open or close. But the data is still updated manually, one record at a time. That is slow and ineffective, and it can’t keep up with how fast things change.

  • Every change has to be found and entered by a person
  • Outdated listings slip through between updates
  • Specialists’ time goes to upkeep instead of people

chapter 3

what that means for people

People don’t get what they need

When a listing is out of date, the person asking for help is sent to a number that no longer works or a program that has closed. They get passed along to another phone number instead of an answer, and some stop looking.

  • Wrong numbers and closed programs become dead ends
  • New services stay invisible until someone adds them by hand
  • The people who most need help pay the price

chapter 4

how we came up with this

What if the system kept itself up to date?

If manual upkeep is what keeps people from help, take the upkeep off people’s hands. The idea started with two resource systems (211 and One Degree) that were too different to connect. Instead of adding more manual work, we automated it.

  • AI agents check and update records automatically
  • Specialists only see the records that need a person
  • Their queue arrives already sorted by zip code

chapter 5

our solution

Five stages, one loop

This is the pipeline we designed. Data flows top to bottom. Keep scrolling to walk through each stage, or jump straight to one.

  • 1Sources & merge↓
  • 2Store & clean↓
  • 3AI maintenance↓
  • 4Verify↓
  • 5Update↓
1

sources

Three sources become one foundation

Records from NDP, ODR and a spreadsheet arrive in different shapes. We standardize every file into the HSDS format first, then merge them into a single Foundation Database. Every later check compares against it.

  • Three sources: NDP, ODR and a spreadsheet
  • Standardize every file into the HSDS format
  • Merge them into the Foundation Database
2

store & clean

Store it, then clean it

The merged data lands in the data store. The database handle then cleans it, so every entry exists exactly once.

  • Data Store holds the merged records
  • Cleaning tidies the raw entries
  • Duplicates are found and handled
3

ai maintenance

AI keeps the data current

AI maintenance runs on Bedrock AgentCore. An agent searches the link on each record, and what it finds decides the next step.

  • Search the agent follows each record’s link
  • Verify confirms the record is real and correct
  • Update refreshes the data with what changed
4

verify

Specialists only see what needs a person

Each record comes out verified or unverified. Verified records go straight into the database with no manual work, and specialists can view them there. Only unverified records need a person’s attention.

  • Verified records are saved to the database automatically, where specialists can view them
  • Unverified records go to a specialist’s queue
  • Sorted by zip code so specialists can work area by area
5

update

Grow it, check it, prune it

The update path runs on its own, so no specialist has to hunt for new listings or chase dead websites.

  • Search for new sources automatically
  • Compare the data with the Foundation Database
  • Every 2 weeks delete websites that don’t respond or haven’t been updated

chapter 6

what changes for specialists

Specialists spend their time where it counts

Today, most of a specialist’s day goes to upkeep: checking links, merging duplicates, hunting for new sources and deleting dead sites. Helping people comes last, if there is time left. With our model, the AI does the routine work, and specialists only see the records that truly need a person.

  • No more checking every record: AI agents verify listings on their own
  • A short, focused queue: only unverified records reach a specialist
  • Sorted by zip code: work area by area instead of record by record
  • Always current data: specialists give answers they can trust
  • More time for people: the hours saved on upkeep go back to helping
