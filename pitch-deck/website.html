team bevijen presents

A database that keeps itself up to date

We automate how community-service information is checked and updated, so specialists spend less time on upkeep and more time helping people.

See how it works ↓ View the code

the problem

Specialists keep resource lists up to date by hand

People who need community services rely on specialists to point them to the right help. When that information is managed manually, specialists spend their time on upkeep, and people often get passed along to another phone number instead of an answer.

  • Every record has to be checked by a person
  • Outdated listings slip through between checks
  • Less time left for the people who need help

how we came up with this

What if the system kept itself up to date?

The idea started with two resource systems (211 and One Degree) that were too different to connect. Instead of adding more manual work, we automated it.

  • AI agents check and update records automatically
  • Specialists only see the records that need a person
  • Their queue arrives already sorted by zip code

our solution

Five stages, one loop

This is the pipeline we designed. Data flows top to bottom. Scroll through each stage, or click a box on the map to jump to it.

1 · Sources & merge 2 · Store & clean 3 · AI maintenance 4 · Verify 5 · Update
1

sources

Two sources become one foundation

Records from NDP and ODR are merged into a single Foundation Database. Every later check compares against it.

  • NDP records come in
  • ODR records come in
  • Merge both into the Foundation Database
2

store & clean

Store it, then clean it

The merged data lands in the data store. The database handle then cleans it, so every entry exists exactly once.

  • Data Store holds the merged records
  • Cleaning tidies the raw entries
  • Duplicates are found and handled
3

ai maintenance

AI keeps the data current

AI maintenance runs on Bedrock AgentCore. An agent searches the link on each record, and what it finds decides the next step.

  • Search the agent follows each record’s link
  • Verify confirms the record is real and correct
  • Update refreshes the data with what changed
4

verify

Specialists only see what needs a person

Each record comes out verified or unverified. Verified records go straight into the database with no manual work, so specialists spend their time only where a person is needed.

  • Verified records are saved to the database automatically
  • Unverified records go to a specialist’s queue
  • Sorted by zip code so specialists can work area by area
5

update

Grow it, check it, prune it

The update path runs on its own, so no specialist has to hunt for new listings or chase dead websites.

  • Search for new sources automatically
  • Compare the data with the Foundation Database
  • Every 2 weeks delete websites that don’t respond or haven’t been updated

in short

Less upkeep, more time to help

The system keeps itself current, and specialists focus on the records that truly need them.

1clean database, kept up to date automatically
2paths per record: verified goes straight in, the rest to a specialist
14days between automatic cleanup sweeps
